# HotWord UI 分析与改版

更新：2026-11-11。先审查现有界面、代码和流程，再浏览 recent.design 首页与组件详情，随后在原项目中实施改版。

## 原界面的问题

1. **步骤没有分开内容。** 原来的准备、审核、导出导航只是滚动锚点，上传、模型面板、审核表与导出预览同时存在；用户必须自己理解整个页面。
2. **配置出现得太早。** 尚未上传资料，就显示项目命名、团队/个人模型、计费、并发额度和输出格式说明。用户的第一个动作被大量次要信息包围。
3. **审核没有主次。** 九列同时展示原词、译文、用途、类别、重要度、必保、依据和删除。经常使用的译法核对与低频高级选项具有同等视觉权重。
4. **重复解释扩大信息量。** 顶部宣传语、阶段标题、规则说明、底部功能介绍和持续展开的设置占用大量空间。
5. **已有动效缺少流程支撑。** 圆角、切换动画和开关已经存在，但没有解决“现在做什么、下一步是什么”的问题。

## 新的信息结构

```
准备资料                 核对词条                    下载词库
上传一个文件       →     修改原词与译文        →     两份 TXT 预览与下载
选择整理方式             确认指定译法                保存审核项目
按需选择范围             按需打开词条详情            按需查看格式与排除原因
```

每次只渲染当前阶段，点击后立即挂载目标内容。焦点与必要的滚动在绘制前完成，步骤条与面板同步更新。数据由工作台统一保存，来回切换继续沿用词条、筛选、分页与文件范围；准备完成前禁用后续步骤。

- **首页：** 一个上传主操作，加上示例与已有项目入口。项目名称由上传文件生成，上传后可修改。资料范围和原文预览默认折叠。
- **整理方式：** 双语表默认沿用原表译法，选择原词/译文列并确认是否跳过表头；普通文字资料显示 AI 提取主操作。AI 服务摘要仅在选择 AI 时出现。
- **核对：** 主要显示原词、译文、热词/指定翻译勾选。长词组自动换行；类别、重要度、必保、原文依据和移除入口放在详情面板。固定在视窗底部的下一步操作，便于长列表处理。
- **下载：** 热词与指定翻译两张结果卡，提供预算、内容预览、复制和 TXT 下载。格式调整与未纳入原因可展开查看；尚未确认的译法有明确提醒及返回入口。
- **辅助信息：** 近期任务、模型与密钥、使用指南通过独立面板打开。大标题只在初始上传页显示，资料就绪后保持三个步骤的导航位置一致。

## 操作反馈与可访问性

- 修改译文会取消指定翻译确认，重新勾选后才按确认规则导出。
- 勾选控件的文字也可点击，支持键盘 Space；筛选使用 `aria-pressed`，步骤使用 `aria-current`，开关使用 `role=switch`。
- 删除词条提供 10 秒撤销，恢复全部属性。删除云端任务仍需确认。
- Radix 面板限制键盘焦点，关闭后回到触发按钮；被移除词条的触发按钮不存在时回到当前流程步骤。
- 折叠内容使用 `inert`，键盘不会进入收起的区域。
- 支持减弱动效设置，停止数字、位移、CSS 过渡；实际操作功能继续可用。
- 次要文字提高对比度；长词组可换行；手机审核采用紧凑卡片行，导出采用单列。
